# Пульс адаптации — правила проекта

Продукт команды InsightForge для кейс-чемпионата «Код города» (МГТС), направление «ИИ и автоматизация процессов».
HR видит, где оценки стажёра и наставника расходятся во времени, понимает причину и получает подсказку, что делать. Решение всегда принимает HR.

Полная спецификация — `docs/SPEC.md`. Дизайн и экраны — `reference/prototype/`. Если код расходится со SPEC, права SPEC; о расхождении сообщи капитану.

## Стек
- Python 3.12, менеджер зависимостей `uv`.
- FastAPI + Uvicorn, Pydantic v2.
- PostgreSQL 16+, SQLAlchemy 2 (async не обязателен), Alembic.
- pandas, numpy, openpyxl, python-docx, rapidfuzz.
- Локальная LLM через Ollama (`qwen2.5:3b-instruct` по умолчанию, `qwen2.5:7b-instruct` — опционально). Любая функция с LLM обязана иметь запасной вариант на правилах.
- Интерфейс: серверные шаблоны Jinja2 + свой CSS + чистый JavaScript (без сборщиков). Живое обновление — Server-Sent Events.
- Streamlit — только `admin/` для внутренней отладки, не для пользователей.
- Docker Compose: `db`, `app`, `ollama`. Запуск одной командой `make up` или `docker compose up`.
- CI: GitHub Actions — ruff, pytest.

## Стиль кода
- Аннотации типов везде, докстринги на русском в стиле Google для публичных функций.
- Бизнес-логика — в `services/`, роутеры тонкие.
- Числа и пороги — в конфиге (`app/core/settings.py` и таблица настроек), не в коде.
- Никаких реальных персональных данных. Только ID и тестовые почты `@pulse.demo`.
- Ошибки пользователю — понятным русским языком.

## Тексты, коммиты, документация
- Пиши как обычная команда разработчиков: деловой русский язык, без лишних слов.
- Не упоминать ИИ-ассистентов и генерацию кода нигде: ни в коде, ни в комментариях, ни в коммитах, ни в документации, ни в описаниях PR. Не добавлять строки вида `Co-Authored-By` и `Generated with`.
- LLM как часть продукта (Ollama, разбор комментариев) — это функциональность, о ней писать можно и нужно.
- Коммиты: `тип(область): что сделано`, по-русски. Типы: feat, fix, refactor, test, docs, chore.
- Коммиты делаются от git-пользователя, настроенного на машине. Не подставлять чужие имена авторов.

## Процесс
1. Работаем по этапам из `docs/SPEC.md`, раздел «Этапы».
2. Один этап — одна ветка `stage-N-кратко`, один PR в `main`.
3. Перед PR: `uv run ruff check --fix && uv run ruff format && uv run pytest -q`.
4. После этапа — отчёт капитану в консоли: что сделано, как проверить, что осталось, риски. И раздел «Что рассказать жюри» — 5–7 пунктов простым языком для участника, отвечающего за эту часть.
5. Ждать слова «дальше» перед следующим этапом. Мерж PR делает капитан после зелёного CI.
6. `docs/STATUS.md` обновлять в конце каждого этапа.

## Нельзя
- Пушить в `main` напрямую, делать `--force` в общие ветки.
- Тянуть данные из интернета во время работы приложения, кроме коннекторов Яндекс/Google Forms, когда они включены.
- Отправлять ответы анкет во внешние LLM. Только локальная Ollama.
- Показывать стажёру ответы наставника и наоборот.
