# Архитектура

```
 Браузер (Jinja2 + свой CSS + чистый JS)          Телефон участника (/survey/{токен})
        │  REST /api/*         ▲ SSE /api/events            │
        ▼                      │                            ▼
 ┌──────────────────────────── FastAPI (app) ─────────────────────────────┐
 │ api/        тонкие роутеры, require_role в каждом эндпоинте             │
 │ services/                                                               │
 │   ingest/     Word + Excel/CSV → схема «Мы поняли так» → записи         │
 │   analytics/  личная норма, сигналы, индекс, прогноз (чистые функции)   │
 │   llm/        клиент Ollama, промпты, 6 задач, запасные правила         │
 │   forms/      своя форма, анкета по ссылке, Яндекс/Google Forms         │
 │   events/     шина SSE                                                   │
 │   dashboard, reports, learning, assistant                               │
 └───────────────┬──────────────────────────────────┬──────────────────────┘
                 ▼                                  ▼
        PostgreSQL 16 (db)                   Ollama (ollama), qwen2.5:3b
        SQLAlchemy 2 + Alembic               только локально
```

## Потоки данных
1. **Загрузка.** `ingest.pipeline.analyze()` разбирает Word (анкеты, вопросы, шкалы) и таблицы (шапка, длинный/широкий формат), определяет стороны, роли колонок, сопоставляет колонки с вопросами (rapidfuzz), предлагает темы и зеркальные вопросы, связывает пары, нормализует шкалы, ищет проблемы качества. HR правит схему на экране, `confirm` пишет данные (`ingest.persist`), сохраняет профиль сопоставления и пересчитывает аналитику.
2. **Живая цепочка.** `forms.submit.submit_response()` → нормализация → `analytics.service.recompute_program(use_llm=False)` → событие `pair_updated` с «было → стало» → дашборды HR перерисовываются. В фоне LLM разбирает комментарий и шлёт уточнённое событие.
3. **Аналитика.** `analytics.core` — чистые функции над рядами `PairSeries` (тестируются без БД). `analytics.service` строит ряды из БД (с учётом смены наставника), считает все месяцы и сохраняет `signals` и `health_snapshots` — поэтому ползунок месяцев на дашборде мгновенный.
4. **LLM.** `llm.client.chat_json()` — строгий JSON по Pydantic-схеме, `temperature=0`, таймаут, повтор, затем `None`. Каждая задача в `llm.tasks` имеет запасной вариант на правилах и поле `fallback`. Проверки: цитата — дословная подстрока, объяснения без новых чисел, ассистент без раскрытия другой стороны.

## Безопасность и данные
- Сессия — HttpOnly-cookie с JWT (12 ч), CSRF — двойная cookie + заголовок, пароли argon2, лимит входа 5/мин.
- Права проверяются на сервере (`core.deps.require_role`); стороны получают только свои данные (`/api/me`), тесты покрывают матрицу ролей.
- В аналитике только ID участников. Ответы анкет не покидают сервер: LLM — локальная Ollama; наружу ходят только коннекторы форм, если включены.

## Масштабирование (после чемпионата)
- Шина SSE и лимит входа живут в памяти процесса: для нескольких воркеров — Redis.
- Пересчёт программы — синхронный (5 пар — миллисекунды); для сотен пар — очередь и пересчёт только затронутой пары.
