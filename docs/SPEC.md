# Пульс адаптации — спецификация

Версия 1.0. Финал чемпионата — 26.11, 3 часа работы на площадке, затем защита.

## 1. Контекст кейса

- Даны: две таблицы Excel (ответы стажёров и ответы наставников) и структура анкет в Word.
- 5 стажёров, 5 наставников, пары 1:1. Каждый заполнял анкету раз в месяц 6 месяцев: 30 анкет стажёров + 30 анкет наставников. Данные синтетические, участники — уникальные ID.
- Точные поля, формулировки вопросов и структура таблиц станут известны только на финале. Поэтому загрузчик обязан распознавать формат сам (раздел 5).
- На защите показывают живую цепочку: **новый ответ → загрузка в систему → анализ → обновление дашборда**. Нужны две формы (стажёр и наставник) и интеграция, ИИ-анализ оценок и комментариев, дашборд «общая картина + детали», сигналы и их причины, исходный код и работающий прототип.
- Ключевая идея кейса — динамика расхождения сигналов стажёра и наставника во времени.

Критерии финала (п. 11.2 положения): соответствие задаче 20%, техническая и методическая обоснованность 25%, практическая реализуемость 20%, эффект и измеримость 20%, качество защиты 15%.

## 3. Регистрация и вход

- `/register` — регистрация HR: имя, рабочая почта, пароль (не короче 10 символов), название организации и программы. Создаёт организацию, программу и пользователя с ролью HR.
- HR создаёт приглашение: почта + роль (руководитель / наставник / стажёр) + для наставника и стажёра — внешний ID из данных (например, `S-104`) или пусто. Ссылка `/invite/{token}` действует 7 дней, одноразовая.
- `/invite/{token}` — человек задаёт имя и пароль, роль и привязка уже заданы.
- `/login` — почта + пароль. Сессия — подписанная HttpOnly-cookie (JWT, 12 часов), CSRF-токен для форм.
- Пароли — argon2. Ограничение попыток входа: 5 в минуту на почту.
- Отправка писем: в демо-режиме письмо не уходит, ссылка показывается HR на экране и пишется в лог. SMTP — опционально через `.env`.
- Демо-аккаунты создаёт команда `make seed`: `hr@pulse.demo`, `lead@pulse.demo`, `mentor@pulse.demo`, `intern@pulse.demo`, пароль в `.env`.

- `import_jobs` (файлы, распознанная схема JSON, отчёт качества, статус), `mapping_profiles` (сохранённое сопоставление для повторной загрузки).

## 5. Умная загрузка — главный модуль

Цель: на финале не трогать код. Всё, что система не поняла, правится на экране.

### 5.1. Поток
1. HR перетаскивает все файлы разом (`.xlsx`, `.xls`, `.csv`, `.docx`).
2. **Классификация файлов:** Excel/CSV — ответы, Word — структура анкет. Для каждой таблицы определяется сторона (стажёр/наставник) по признакам с весами:
   - имя файла и листа (`стаж`, `intern`, `наставн`, `mentor`);
   - заголовки колонок;
   - формат ID (префиксы, разные множества ID в двух файлах);
   - совпадение заголовков с вопросами анкет из Word (rapidfuzz);
   - если сумма признаков неубедительна — LLM; если и она не уверена — вопрос пользователю.
3. **Разбор Word** (python-docx: абзацы и таблицы): находит анкеты, заголовки разделов, вопросы, тип вопроса (шкала, выбор, текст), диапазон шкалы, подписи краёв шкалы. Если в одном файле обе анкеты — делит по заголовкам.
4. **Распознавание колонок Excel** (по заголовку и содержимому):
   - ID участника: строки с повторяющимся шаблоном, ~5 уникальных значений, повтор 6 раз;
   - связь пары: колонка с ID другой стороны или общий ID пары;
   - период: даты, номера 1–6, названия месяцев, «месяц 3»;
   - оценки: числа в узком диапазоне или словесная шкала;
   - комментарии: длинные строки;
   - служебные поля: отметка времени, почта, подразделение.
   Поддержать оба формата: «широкий» (строка = анкета) и «длинный» (строка = ответ на вопрос). Лишние листы, объединённые ячейки и многострочная шапка не должны ломать разбор.
5. **Сопоставление колонок с вопросами** Word: нормализация текста, rapidfuzz, затем LLM для спорных.
6. **Темы и зеркальные вопросы:** LLM предлагает тему каждого вопроса и пару «вопрос стажёру ↔ вопрос наставнику». Запасной вариант — словарь ключевых слов по темам.
7. **Пары:** по колонке связи; если её нет — по совпадению ID-шаблонов (`S-104`/`M-204`); если нельзя — HR связывает на экране.
8. **Нормализация:** любая шкала → 0–1; словесные ответы («совсем нет … полностью», «не согласен … согласен») — по словарю; инверсные вопросы помечаются флагом и переворачиваются.
9. **Проверка качества:** пропуски, дубли, ID не по шаблону (похожий существующий ID — предложить исправление), разные шкалы, месяцы вне диапазона, пары без второй стороны.
10. **Экран «Мы поняли так»:** каждое решение с уверенностью (0–1) и цветом; любое меняется выпадающим списком; проблемы качества — с кнопкой исправления; «Подтвердить» → запись в БД → пересчёт аналитики → событие SSE.
11. **Профиль сопоставления** сохраняется: следующая загрузка того же формата идёт без вопросов.

### 5.2. Тестовые файлы (обязательно, `tests/fixtures/ingest/`)
Генератор `ml/make_fixtures.py` создаёт минимум 6 вариантов пар «Excel стажёров + Excel наставников + Word»:
1. широкий формат, русские заголовки = формулировки вопросов, шкала 1–5, номер месяца;
2. длинный формат (строка = ответ), английские коды вопросов `Q1…Q8`;
3. шкала 1–10 у наставников и 1–5 у стажёров, даты вместо месяцев;
4. словесная шкала, названия месяцев, комментарии в двух колонках;
5. лишний лист «Инструкция», объединённые ячейки, двухстрочная шапка;
6. опечатки в ID (`S-1O4`), один дубль, три пропуска, обе анкеты в одном Word.
Тест: загрузчик распознаёт каждый вариант без ручного вмешательства (или с вопросами только по тем пунктам, где это ожидаемо), результат совпадает с эталоном.

Запасной путь: `docs/template.xlsx` — шаблон, к которому данные можно быстро привести руками.

## 6. Аналитика

Все оценки → шкала 0–1. Расчёт по темам и по паре в целом (среднее по темам). Δ = оценка стажёра − оценка наставника по одной теме, |Δ| — модуль.

### 6.1. Личная норма
Норма человека по теме — медиана его первых двух месяцев (если месяцев меньше — по имеющимся). Для сигнала «уровень» используются отклонения от нормы, чтобы «щедрый» и «строгий» оценщики сравнивались честно. Сырые значения сохраняются и показываются рядом.

### 6.2. Четыре сигнала
| Сигнал | Правило (стартовые пороги в настройках) | Действие HR |
|---|---|---|
| Уровень | \|Δ\| ≥ 0,25 два месяца подряд | Сверить ожидания |
| Растущий разрыв | наклон \|Δ\| за последние 3 месяца ≥ 0,05 в месяц | Встреча втроём |
| Запаздывание | одна сторона снизила оценку темы ≥ 0,1, другая нет; число месяцев без реакции | Показать расхождение той стороне, что не видит |
| Слова ≠ цифры | оценка ≥ 0,7, а тревожность комментария ≥ 0,6 (LLM или словарь) | Личная беседа |

Дополнительно:
- **Сигнал программы:** тема проседает (снижение ≥ 0,1 за месяц) у ≥ 60% пар в одном месяце → «проверить программу», не «проблема людей».
- **Неполнота данных:** пропуск анкеты показывается отдельно и не считается проблемой.
- **Прогноз:** \|Δ\| на месяц вперёд = последнее значение + наклон; «до красной зоны» (\|Δ\| ≥ 0,5) — в месяцах. Помечается как ориентир.

### 6.3. Индекс здоровья пары (0–100)
`index = max(5, 100 − сумма штрафов)`, каждый штраф виден в карточке пары.

| Штраф | Формула | Стартовый вес |
|---|---|---|
| Уровень разрыва | \|Δ\| последнего месяца (по личной норме) × w | 60 |
| Рост разрыва | max(0, наклон \|Δ\| за 2 мес.) × w | 250 |
| Падение оценок | max(0, оценка 1-го месяца − текущая) по худшей стороне × w | 60 |
| Низкий общий уровень | max(0, 0,6 − средняя оценка пары) × w | 120 |
| Слова ≠ цифры | противоречие комментария баллам 0–1 × w | 30 |
| Запаздывание | месяцев без реакции × w | 5 (новый штраф) |
| Нет анкеты | фикс. | 8 |

Веса и пороги — в таблице `settings`, редактируются на экране «Настройки». В документации: «стартовые веса, согласуем с HR и калибруем на исторических данных».

### 6.4. Проверка детектора
`ml/validate.py`: генерирует N синтетических пар по сценариям — переоценивает себя, наставник не видит тревоги, перегруз наставника, слова ≠ цифры, здоровая пара — и считает:
- на каком месяце сработал сигнал против месяца, когда сценарий заложен;
- долю ложных тревог на здоровых парах.
Итог — `docs/VALIDATION.md` и таблица в справочнике приложения. Цифры только из реального прогона.

### 6.5. Эффект
- На сколько месяцев раньше сигнал виден, чем просадка среднего балла пары (по истории).
- Доля сигналов, подтверждённых HR (кнопки «подтверждаю / ложная тревога»).
- У скольких пар после действия разрыв сократился в следующей анкете.
- Время анализа HR: сколько уходит на ручное сопоставление против работы с дашбордом (замер на демо).

## 7. LLM (Ollama)

- Модель по умолчанию `qwen2.5:3b-instruct` (укладывается в 4–6 ГБ видеопамяти RTX 3050 Laptop), `qwen2.5:7b-instruct` — если хватает памяти. Имя модели — в `.env`.
- Все ответы — строгий JSON по Pydantic-схеме, `temperature=0`, таймаут, повтор при невалидном JSON, затем запасной вариант на правилах. В результате поле `fallback`.
- Задачи:
  1. `classify_table` — сторона таблицы, когда признаков мало.
  2. `map_question_topic` — тема вопроса и зеркальный вопрос.
  3. `analyze_comment` — темы, тон, тревожность, противоречие с баллами, короткая цитата из текста (дословно, проверять вхождением).
  4. `explain_signal` — причина сигнала простыми словами по фактам из БД (никаких выдуманных цифр: передаём числа, LLM только формулирует).
  5. `meeting_agenda` — повестка встречи втроём по сигналам пары, без сырых ответов сторон.
  6. `meeting_outcomes` — договорённости «кто / что / когда» из свободного текста итогов.
  7. `assistant_chat` — ответы с учётом роли (этап 8).
- Промпты лежат в `app/services/llm/prompts/*.md`, на русском.
- Кэш результатов разбора комментариев по хешу текста.

## 8. Формы и живая цепочка

- **Своя форма** (`/survey/{token}` и раздел «Моя стажировка»): анкета строится из `questions` нужной стороны; отправка создаёт `response`.
- **Яндекс Формы:** коннектор по API ответов (токен и ID формы в настройках) — периодический опрос новых ответов каждые 15 секунд; плюс приёмник входящих HTTP-запросов `/api/forms/yandex/webhook` для интеграции «Отправить HTTP-запрос». Сопоставление полей формы с вопросами — тем же механизмом, что в загрузке.
- **Google Forms:** коннектор через Forms API (`responses.list`), OAuth-данные в `.env`; опрос каждые 15 секунд.
- Без токенов коннекторы выключены, интерфейс показывает «не подключено» и инструкцию в `docs/FORMS.md`.
- Любой новый ответ → нормализация → разбор комментария → пересчёт сигналов и индекса пары → событие SSE `pair_updated` с разницей «было → стало» → дашборд обновляет виджеты и показывает всплывающее «С-104 ответил: тренд П-04 вырос, индекс 47 → 41».
- Кнопка демо «Отправить тестовый ответ» для HR в демо-режиме — запасной путь для защиты.

## 9. Экраны (по `reference/prototype/`)

Внешний вид, тексты, цвета и поведение берутся из прототипа. Ключевые требования:
- Без тёмного бокового меню: липкая верхняя панель с сегментированной навигацией, поиск и команды, уведомления, меню профиля.
- Цвета: фон `#F3F5F9`, тёмные блоки `#070A14` с синими радиальными «сферами», карточки `#FFFFFF` с рамкой `#E3E6EC`, акцент `#0A7CD6`, второй `#4F6BDA`. Шрифты Unbounded (заголовки) и Onest (текст) — скачать и положить в `static/fonts`, без внешних CDN.
- Кнопки и элементы управления — не меньше 44 px, настоящие `<button>` и `<label>`, клавиатурная навигация, адаптив до 360 px.

Список:
1. Главная (лендинг): «Два взгляда на одну стажировку», четыре сигнала, как работает, роли.
2. Вход. 3. Регистрация HR. 4. Принятие приглашения.
5. Дашборд: приветствие, «Настроить» (порядок ↑/↓, скрыть, полка виджетов, пресеты; раскладка сохраняется на сервере), фильтры по периоду (ползунок месяцев) и подразделению, «Отчёт». Виджеты: ключевые показатели, мои задачи на неделю, сигналы, карта пар (квадранты), динамика расхождения с прогнозом, проблема пары или программы, анкеты за месяц, комментарии с разбором, индекс здоровья.
6. Пары: список с поиском и фильтрами + карточка. Вкладки: Диагноз (разложение расхождения, график двух линий с прогнозом, переключатель «сырые / личная шкала», штрафы индекса, тепловая карта Δ по темам), Люди, комментарии, заметки HR, Действия (жизненный цикл, итоги встречи с договорённостями, повестка от LLM). Пустое состояние для новой пары.
7. Программа: пары (подбор наставника с ранжированием, смена наставника с отметкой на графике), участники и приглашения, поток и итоги стажировки.
8. Анкеты: рассылки (статусы, напоминания, каналы, предпросмотр), конструктор (версии, тема и зеркальный вопрос от LLM, покрытие тем), источники и загрузка (экран из раздела 5).
9. Моя стажировка (стажёр и наставник): анкета, свои оценки по темам, темы для разговора, «Хочу поговорить с HR», каналы напоминаний.
10. Обучение: курсы, тесты (генерация вопросов LLM по материалу с проверкой HR), справочник по методике (из `docs/METHODOLOGY.md`).
11. Настройки: интеграции, состояние LLM, правила оповещений с порогами и превью «сработало бы сейчас», роли и доступ.
12. ИИ-ассистент: плавающая кнопка и панель чата.

## 12. Сценарий демонстрации (основа для `docs/DEMO.md`)
1. Вход HR → загрузка трёх файлов → экран «Мы поняли так» → подтверждение.
2. Дашборд: 4 из 5 пар в зоне внимания, сигнал программы, карта пар.
3. Карточка проблемной пары: разложение расхождения, график с прогнозом, цитата из комментария, рекомендация.
4. Живая цепочка: член жюри или участник заполняет анкету с телефона → через секунды дашборд показывает изменение.
5. Действие: назначить встречу втроём, повестка от LLM, итоги → договорённости.
6. Справочник: как проверяли детектор и чего система не обещает.
