# Развёртывание

Два варианта: **ноутбук + сервер-посредник** (дёшево, модель на видеокарте ноутбука) и **сервер с GPU** (всё на арендованном сервере).

## Ноутбук + сервер-посредник

Приложение и модель работают на ноутбуке. Дешёвый VPS в РФ без видеокарты принимает HTTPS на домене и передаёт запросы на ноутбук по SSH-туннелю. Ноутбук сам подключается к серверу, поэтому белый IP и настройка роутера не нужны.

```
браузер ──HTTPS──▶ VPS: caddy:443 ──▶ 127.0.0.1:8000 ══SSH-туннель══▶ ноутбук: app ──▶ db, ollama (GPU)
```

### Что нужно
- VPS: Ubuntu 22.04/24.04, 1 vCPU, 1 ГБ RAM, публичный IPv4, регион Москва. При заказе добавить открытый ключ `~/.ssh/pulse_admin.pub`.
- Домен с A-записью на IP сервера.
- Ноутбук: Docker, видеокарта NVIDIA с nvidia-container-toolkit.

### Первый запуск
```bash
ssh-keygen -t ed25519 -N "" -f ~/.ssh/pulse_admin    # ключ администратора, если ещё нет
ssh-keygen -t ed25519 -N "" -f ~/.ssh/pulse_tunnel   # ключ туннеля
make edge-setup EDGE=IP DOMAIN=pulse.example.ru       # подготовить сервер: Caddy, пользователь tunnel, ufw
make laptop-up                                        # приложение на ноутбуке, модель прогрета
make tunnel-install EDGE=IP                           # туннель как служба пользователя, переподключается сам
```
Открыть `https://pulse.example.ru`.

### Как это устроено
- На ноутбуке порт 8000 открыт только для `127.0.0.1`, база и Ollama наружу не смотрят.
- Пользователь `tunnel` на сервере может только открыть обратный туннель на `127.0.0.1:8000`: ни терминала, ни доступа к другим портам сервера.
- Пока служба туннеля работает, ноутбук не засыпает и не реагирует на закрытие крышки. Остановить: `make tunnel-stop`.
- Если ноутбук выключен или туннель оборван, на домене видна страница «Демо-стенд сейчас выключен» вместо ошибки.
- Состояние туннеля: `make tunnel-status`. Остановить приложение: `make laptop-down`.
- Перед показом: `make demo` — свежие демо-данные.

## Сервер с GPU

Схема: сервер с видеокартой NVIDIA в РФ, домен, HTTPS. Снаружи открыты только порты 80 и 443 (Caddy), база и Ollama доступны лишь внутри сети Docker. Данные и модель не покидают сервер.

```
браузер ──HTTPS──▶ caddy:443 ──▶ app:8000 ──▶ db:5432
                                         └──▶ ollama:11434 (GPU)
```

### Что нужно

- Сервер: Ubuntu 22.04/24.04 с драйверами NVIDIA, GPU от 16 ГБ видеопамяти (T4, A2, A4000 и аналоги), 4+ vCPU, 16 ГБ RAM, 50+ ГБ диска. Удобнее брать образ провайдера с уже установленным драйвером.
- Домен с A-записью на IP сервера. Проверка: `dig +short pulse.example.ru` возвращает IP.
- Доступ по SSH с ноутбука (ключ).

### Первый запуск

1. Скопировать скрипт на сервер и выполнить его. Скрипт ставит Docker и nvidia-container-toolkit, открывает порты 22/80/443, создаёт `/opt/pulse/.env` со случайными секретами и ночной сброс демо-данных.
   ```bash
   scp deploy/server-setup.sh root@IP:/root/
   ssh root@IP 'bash /root/server-setup.sh pulse.example.ru'
   ```
   В конце скрипт печатает демо-пароль.
2. С ноутбука, из корня репозитория:
   ```bash
   make deploy HOST=root@IP
   ```
   Команда копирует код на сервер (`.env` на сервере не трогается) и выполняет `make prod-up`: сборку, скачивание модели, прогрев, демо-данные при пустой базе. Сертификат Let's Encrypt Caddy выпускает сам при первом обращении к домену.
3. Открыть `https://pulse.example.ru`, войти под демо-аккаунтом.

### Обновление

`make deploy HOST=root@IP` — тот же шаг. База и модель сохраняются в томах Docker.

### Команды на сервере (`cd /opt/pulse`)

| Команда | Что делает |
|---|---|
| `make prod-up` | собрать и запустить, скачать и прогреть модель |
| `make prod-warm` | загрузить модель в видеопамять и сделать пробный запрос |
| `make prod-demo` | пересоздать демо-данные (комментарии разбирает модель) |
| `make prod-logs` | журналы приложения и Caddy |
| `make prod-down` | остановить |

Демо-данные пересоздаются каждую ночь в 4:00 по Москве (`/etc/cron.d/pulse-demo`). Перед показом жюри — `make prod-demo` вручную.

### Скорость ответов

- Модель загружена в видеопамять постоянно (`OLLAMA_KEEP_ALIVE=-1`), холодного старта нет. Первый запрос после загрузки идёт дольше обычного, поэтому `make prod-warm` делает его заранее.
- Повторный одинаковый запрос к модели отдаётся из памяти приложения (`LLM_CACHE_SIZE`, по умолчанию 512 ответов): при `temperature=0` ответ всё равно был бы тем же.
- Длина ответа модели ограничена `LLM_MAX_TOKENS` (1024), зависшая генерация не держит запрос до таймаута.
- Замер на RTX 3050 4 ГБ: разбор комментария ~2 с, объяснение сигнала ~5 с, повтор из кэша 0,01 с, страницы — десятки миллисекунд. На серверной видеокарте генерация в несколько раз быстрее.

### Если что-то не так

- Сертификат не выпускается — проверить A-запись домена и что порт 80 открыт у провайдера (не только в `ufw`).
- `could not select device driver "nvidia"` — не установлен nvidia-container-toolkit или Docker не перезапущен: повторить `server-setup.sh`.
- Не скачиваются образы Docker — скрипт прописывает зеркало `mirror.gcr.io`; у провайдера может быть своё зеркало, его можно добавить в `/etc/docker/daemon.json`.
- Модель скачивается медленно — перенести с ноутбука: `docker run --rm -v insightforge-pulse_ollama:/d alpine tar czf - -C /d . > ollama.tgz`, скопировать на сервер и распаковать в том `pulse_ollama`.
- На экране «Настройки» видно состояние модели и задержку ответа.
